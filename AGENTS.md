# AGENTS.md

> Canonical entry point for AI agents working in this repository. Tool-agnostic: Kiro, Claude Code, Cursor, Copilot, Codex.
> Everything in this repository (code, comments, docs, commit messages, PRs) is written in **English**.
> The only Portuguese allowed is **user-facing UI copy**, **LLM prompts/summaries for end users**, and **verbatim legal data** (court movement titles/contents).

## Project overview

A web app where a user types a Brazilian CNJ lawsuit number (e.g. `1002271-82.2025.8.26.0003`) and gets:

1. the lawsuit data and the list of court movements, laid out like the TJSP e-SAJ page;
2. a plain-language summary (max 3 paragraphs, no legalese) generated by an LLM from the movements.

Data comes from `data/lawsuits_movements.csv` (100 lawsuits, 5,568 movements), imported into a relational database. We do **not** scrape the court website.

Source of truth for requirements: [`data/Desafio Técnico com IA - 2026.md`](data/Desafio%20Técnico%20com%20IA%20-%202026.md).
Hard constraints from the challenge: automated tests covering **>= 80%**, a relational DB, a README with run instructions and technologies, this `AGENTS.md`, English commit messages, **no commits after the deadline**.

## Target stack (see [ADR-0001](docs/adr/0001-technology-stack.md))

| Layer | Choice |
|-------|--------|
| Backend | Ruby on Rails (API mode), `graphql-ruby` |
| Database | PostgreSQL |
| Frontend | React + TypeScript + Vite + Apollo Client, WCAG 2.2 AA |
| LLM | Gemini (REST, key in `GEMINI_API_KEY`) behind `Llm::Client`; `fake` provider for dev/test ([ADR-0002](docs/adr/0002-llm-provider-abstraction.md)) |
| Tests | RSpec + SimpleCov (backend), Vitest + Testing Library (frontend), Playwright E2E + axe (frontend/playwright) |
| Runtime | Docker Compose (host Ruby is 3.0, so never rely on host Ruby) |

## Execution principles

1. **Simplicity.** Smallest change that satisfies the requirement. No speculative abstractions, flags or config.
2. **Surgical edits.** Touch only what the task needs. No drive-by refactors or mass renames.
3. **Verifiable goal.** State what must be true when done (a test, a screen, a query result) before coding.
4. **Clarify, do not assume.** If a requirement is ambiguous, ask or record the assumption in the spec/ADR.

## Rules for agents

- **TDD is mandatory.** Write the failing test first (Red), make it pass (Green), then refactor. See [write-tests-tdd.md](docs/skills/write-tests-tdd.md).
- **Coverage gate: backend line coverage >= 80%** (SimpleCov `minimum_coverage 80`, build fails below). Frontend target >= 80% as well.
- **No code before an approved plan** for non-trivial work: spec `tasks.md` counts as the plan; deviations need an ADR or a note in the spec.
- **Never commit secrets.** API keys live in ENV / `.env` (git-ignored). Commit only `.env.example`.
- **Never call a real LLM in tests.** Use the `fake` provider or stubbed HTTP (WebMock).
- **Plain language is a product requirement.** Any change to the summary prompt must be checked against [legal-glossary.md](docs/domains/legal-glossary.md) and [tune-llm-summary.md](docs/skills/tune-llm-summary.md).
- **Do not give legal advice.** The summary explains what happened; it never predicts outcomes or recommends actions. UI shows a short disclaimer.
- **Minimize PII sent to the LLM.** Strip lawyer names/OAB lines before building the prompt. Never log full prompts or movement contents above `debug` level.
- **Commits:** English, Conventional Commits (`feat:`, `fix:`, `test:`, `docs:`, `chore:`, `refactor:`), small and atomic. **No commits after the challenge deadline.**
- **Branches:** `feat/<spec-number>-<slug>`, `fix/<slug>`, `docs/<slug>`; PR to `main`. Do not push directly to `main` unless the owner asks.
- **Do not edit** `data/lawsuits_movements.csv` or the challenge statement.
- After finishing a task, tick it in the spec `tasks.md` and run [finish-delivery-docs.md](docs/skills/finish-delivery-docs.md).

## Common commands

> Verified against the actual repo as of spec 08 (quality-and-delivery). See the [README](README.md#getting-started) for the full list, including lint/security/codegen commands.

```bash
cp .env.example .env                                        # set HOST_UID/HOST_GID, SECRET_KEY_BASE, GEMINI_API_KEY
docker compose up --build                                   # db + api (3000) + web (5173)
docker compose run --rm api bin/rails import:lawsuits        # CSV import (also runs on first container start)
docker compose run --rm -e RAILS_ENV=test api bundle exec rspec   # backend tests + coverage gate (RAILS_ENV=test is required)
docker compose run --rm web npm test -- --run                # frontend tests
docker compose run --rm api bundle exec rubocop               # backend lint
docker compose run --rm web npm run lint                      # frontend lint
(cd frontend && PLAYWRIGHT_CHROME_PATH=/usr/bin/google-chrome npm run test:e2e)   # E2E + axe against the running stack (LLM_PROVIDER=fake)
docker compose run --rm api bin/contract_check                 # GraphQL schema vs. docs/contracts/schema.graphql
docker compose run --rm api bin/rails feedback:report            # helpful rate per prompt_version and model
docker compose run --rm api bin/rails summaries:eval           # print golden-set summaries (needs GEMINI_API_KEY; ALLOW_FAKE=1 for offline)
```
