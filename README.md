# consulta-processo-juridico

Lawsuit lookup for Brazilian CNJ numbers. The user enters a CNJ number and sees the lawsuit data, the court movements (laid out like the TJSP e-SAJ page) and a plain-language summary generated by an LLM.

Built for the Resolvvi technical challenge (see [`data/Desafio Técnico com IA - 2026.md`](data/Desafio%20Técnico%20com%20IA%20-%202026.md)).

> **Status:** all eight specs are implemented: CSV import, lawsuit lookup (GraphQL), AI summary, lookup UI, authentication, summary feedback, and the quality gates. Remaining delivery steps (demo video, sharing, email) are manual, see [prepare-delivery](docs/skills/prepare-delivery.md).

## Getting started

### Prerequisites

- Docker and Docker Compose v2 (`docker compose version`). The host's own Ruby/Node are **not** used; everything runs in containers.
- A Linux/macOS host user whose UID/GID you know (`id -u`, `id -g`) if they are not `1000` — see the `.env` note below.

### 1. Configure environment

```bash
cp .env.example .env
```

Edit `.env` and set:

- `HOST_UID` / `HOST_GID`: run `id -u` and `id -g` on your machine. If both are `1000` (the common case on a fresh Linux/macOS install) you can leave the defaults. If they differ, the `api`/`web` containers will fail with permission errors on bind-mounted files until you set these correctly.
- `SECRET_KEY_BASE`: any long random string for local dev, e.g. `openssl rand -hex 64`.
- `GEMINI_API_KEY`: optional. Leave empty to use the deterministic `fake` LLM provider (`LLM_PROVIDER=auto` falls back to it automatically). Get a key at [Google AI Studio](https://aistudio.google.com/) if you want real Gemini summaries.

### 2. Start the stack

```bash
docker compose up --build
```

This builds and starts `db` (Postgres), `api` (Rails, port `3000`) and `web` (Vite dev server, port `5173`). The API entrypoint waits for the database, runs `db:prepare` and imports the CSV when the `lawsuits` table is empty.

- Health check: `curl http://localhost:3000/up` should return `200`.
- Frontend: open `http://localhost:5173/`.
- GraphQL: `POST http://localhost:5173/graphql` (proxied to the API) or `POST http://localhost:3000/graphql` directly.

### 3. Import the challenge data

On an empty database the `api` container imports `data/lawsuits_movements.csv` automatically at startup (via `db:seed`) and prints a report (100 lawsuits, 5568 movements, 0 skipped rows). Later starts skip the import. To run it by hand (idempotent, safe to repeat):

```bash
docker compose run --rm api bin/rails import:lawsuits                              # path from LAWSUITS_CSV_PATH
docker compose run --rm api bin/rails "import:lawsuits[/data/lawsuits_movements.csv]"
```

The task exits with status 1 and a clear message if the file is missing, unreadable, malformed or lacks a required header.

### First account
There is no seeded user. Open `http://localhost:5173/`, you are sent to the login page; choose **Criar conta** and register with any e-mail and a password of 10 to 72 characters. The session lasts 14 days; **Sair** ends it. Sign-in and sign-up are throttled (5 attempts per minute, 10 sign-ups per hour per IP).
To try the lookup, search `1001399-31.2023.8.26.0070` (found). `1002271-82.2025.8.26.0003` is a valid CNJ number that is not in the data and shows the not-found state.
### AI summary (LLM)
The summary is generated on demand by `generateSummary` and cached per lawsuit, movements, prompt version and model (see [ai-summary](docs/domains/ai-summary.md)). Configure it in `.env`:
- `LLM_PROVIDER`: `auto` (default; Gemini when `GEMINI_API_KEY` is set, otherwise the offline `fake` provider), `gemini` or `fake`. The test environment always uses `fake`, so tests never reach the network.
- `LLM_MODEL` / `LLM_FALLBACK_MODEL` / `LLM_TIMEOUT_SECONDS`: model ids (defaults in `.env.example`) and the per-attempt timeout.
- The `fake` provider returns a deterministic pt-BR text built from the lawsuit data, so the whole flow is demoable without a key.
To review real summaries for the golden set (needs `GEMINI_API_KEY`, not part of CI; add `-e LAWSUITS=n1,n2` to pick lawsuits):
```bash
docker compose run --rm api bin/rails summaries:eval
```

### Reading the summary feedback

Signed-in users vote with **Útil** / **Não foi útil** under each summary (one vote per user and summary; voting again changes it). The team reads the results per prompt version and model:

```bash
docker compose run --rm api bin/rails feedback:report
```

It prints summaries, votes, helpful, not helpful and the helpful rate per `prompt_version` and `model` (or "No feedback votes yet."), and never prints user data.

### 4. Run the tests

```bash
# Backend: RSpec + SimpleCov (fails the build below 80% line coverage)
# RAILS_ENV=test is required explicitly: the api service sets RAILS_ENV=development
# by default, which overrides rails_helper's own ENV['RAILS_ENV'] ||= 'test' fallback.
docker compose run --rm -e RAILS_ENV=test api bundle exec rspec

# Backend: lint and security
docker compose run --rm api bundle exec rubocop
docker compose run --rm api bundle exec brakeman -q --no-pager
docker compose run --rm api bundle exec bundler-audit check  # downloads the advisory db on first run

# Backend: GraphQL contract drift check (compares against docs/contracts/schema.graphql)
docker compose run --rm api bin/contract_check

# Frontend: lint, typecheck, unit tests, build
docker compose run --rm web npm run lint
docker compose run --rm web npm run typecheck
docker compose run --rm web npm test -- --run --coverage
docker compose run --rm web npm run build

# Frontend: end-to-end flow with axe checks against the running stack (docker compose up).
# Runs on the host (Node 22) against http://localhost:5173. Needs a browser: `npx playwright install chromium`,
# or set PLAYWRIGHT_CHROME_PATH=/usr/bin/google-chrome to reuse a local Chrome.
(cd frontend && npm ci && npm run test:e2e)
# Frontend: regenerate GraphQL types from backend/schema.graphql after a schema change
docker compose run --rm web npm run codegen
```

All of the above are run the same way in CI (see [`.github/workflows/ci.yml`](.github/workflows/ci.yml)).

## Assumptions and limits

- Only lawsuits in the CSV can be found. The challenge example `1002271-82.2025.8.26.0003` is a valid CNJ number that is not in the data, so it shows the "not found" state by design.
- Movements are shown newest first; movements on the same date keep the CSV row order (`source_row`).
- Authentication is email and password only: no password reset and no email verification.
- The summary is generated synchronously on first view and cached per lawsuit, movements, prompt version and model. Lawyer names and OAB lines are removed before the text reaches the LLM.
- The summary explains what happened; it does not predict outcomes or give legal advice, and the page shows a disclaimer.
- Plain-language quality is a human judgment. The `summaries:eval` task prints summaries for the golden set; a review by a legal expert of a real Gemini run was not part of the automated work and is still open before delivery.
- Throttling counters live in process memory, which is fine for the single-container demo.
- The manual accessibility checks (keyboard-only, screen reader, zoom) listed in the [accessibility audit](.kiro/specs/08-quality-and-delivery/accessibility-audit.md) are still open.
